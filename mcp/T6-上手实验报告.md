## 4. schema 能不能过校验？第一次为什么不过？是谁的问题？

**第一次：完全过不了 —— 直接崩。**

我按最直觉的方式写：`container.includes: ["<cstdint>"]`（字符串列表）、
`vocabulary_schema: {required: [...], optional: [...]}`。工具回：

```json
{"ok": false, "error": "AttributeError: 'str' object has no attribute 'get'"}
```

**没有任何结构化的"你第几项错了"**，只有一个裸异常字符串。我只能靠二分（v1–v4）反推。

**根因归属：工具描述（不是我的锅）。** 两条隐藏契约，工具的自描述里**一个字都没提**：

1. `container.includes` 与 `container.order` 必须是 **mapping 列表**（如 `[{"name": "cstdint"}]`）。
   我的"字符串列表"是 `includes` 这个词最自然的读法，却直接触发无信息崩溃。
2. `vocabulary_schema` 的**顶层键名**被当成"每个 vocabulary 的必填字段名"。
   我写 `required:` / `optional:`，工具就报告 `vocabulary[TD] missing: ["required","optional"]`——
   它在问我的词表为什么没有叫 "required" 的字段。这条契约**反直觉且无出处**。

**修正后**：`structure.ok=true`、`vocabulary[TD] missing=[]`——**我过了结构校验**。
但 **round-trip 永远 FAIL**：`hosts:{}`、`stdout:[]`、零诊断。原因见 §5 缺口#2。

> 诚实备注：`structure.ok` 只证明**键名齐全**。工具明说"不校验 C++ 表达式/别名的语义正确性"，
> 而我手写的 `ColTri` 声明 `static_assert(sizeof==0x28)` 但实际 52 字节——这类错**结构校验查不出**，
> 是后来跑 `run_demo.py` 的 ABI 断言才炸出来的（"ColTri: ctypes.sizeof=52 violates static_assert ==40"）。**我错了这一处。**

## 5. 工具自描述在哪里不够用 —— 逐条（这是本实验的核心产出）

### 🥇 三大缺口

**缺口 A — "schema 的 schema" 完全缺失，两条隐藏契约只在崩溃时暴露。**
- 我想知道：`schema.yaml` 每个字段的长相（类型、可取值、示例）。
- 工具没告诉我：`pt_schema_validate` 只**校验** schema，不给模板、不给 JSON-Schema、不给示例。
  `REPORT.md` 里的 schema 全文也只有**3 个 host 的实例**，没有一个字段级说明。
- 我只能：**逆读工具自己的产物**——从 `tools/layout_from_schema.py`（scaffold 拷贝的）
  读出 `vocabularies[host]` 需要 `host_abbr / magic / version / mapping_name / units_per_block /
  host_state{fields,size} / mc_state / host_flags / mc_flags / input_type / hurt_flags /
  mc_event_type / ren_type`；从 `protocol/SKY.proto.h` 反推 `container.regions_template` 的写法。
- 代价：`includes/order/vocabulary_schema` 三条契约是靠**崩溃-二分**试出来的，不是我"读"出来的。

**缺口 B — round-trip 只认内置 3 宿主，新宿主完全无法验证。**
- 我想知道：我写的 Teardown 词表**对不对**。
- 工具没告诉我：round-trip 固定对 SKY/FO4/VAL 跑 `extract→generate→structural-diff`。
  我即使 `structure.ok=true`，round-trip 仍返回 `{"hosts": {}, "exit_code": 1,
  "conclusion": "FAIL: a MIT host did not round-trip to zero."}`——**stdout 为空、无任何诊断**。
- 我只能：接受"结构过了就算过了"，语义正确性**完全无法自证**。这恰恰是新人最需要的验证。

**缺口 C — scaffold 的建议自相矛盾，闭环断掉。**
- 工具警告我："请把 Teardown 的 vocabulary 补进 schema.yaml 再重跑"。
- 但：(a) `pt_scaffold` 的输入只有 `{host, guest, out_dir}`，**没有 `schema_path` 参数**，永远读默认 `v0-schema/schema.yaml`；
  (b) 生成的 `tools/run_demo.py` **硬编码** `L.verify("SKY")`、`fake_host` 硬编码 `sky` 前缀 →
  我补了 TD 词表也**跑不了我的宿主**（实测报 `unknown host 'SKY'; have ['TD']`）；
  (c) "补进 schema.yaml" 要求改只读的 `v0-*`，而工具自己声明"不写 `v0-*`"。
- 我只能：把修正后的词表**另存**在 `T6-output/schema.teardown.yaml`，并**手工**承认"这批产物仍是 SKY 的"。

## 6. TODO-MEASURE.md 的覆盖情况

- 工具自动生成部分：命中 **11 条 🔴 必须实测**参数，**全部保留**（覆盖了工具自己口径的 must-measure 类）。
- **但其宿主维度是错的**：11 条全属 Skyrim/GTA5/Valheim，因为 Teardown 未注册、工具退化到"按客侧(Minecraft)匹配"。
  → 工具**为我的宿主贡献了 0 条**。
- 我据此**手工增补 8 条 Teardown 宿主侧**待实测项（`td.units_per_block` / `yaw_pitch_expr` /
  `voxel_scale` / `slope_threshold_deg` / `vertical_extent` / `epoch_semantics` / `natives_hook` /
  `overlay_compositing`），每条都引用了工具自己的 `does_not` 或参数库 caveats 作为"为什么必须实测"的依据。
- **覆盖面结论**：对"工具标记为必须实测的**类**"覆盖良好（19 条）；
  对"**我的宿主**的必须实测项"工具帮助为 0，全靠人手补——而这正是新宿主的全部工作量。

## 9. 给工具作者的三条改法建议（基于以上缺口）

1. **给 `pt_schema_validate` 加一个 `template`/`explain` 模式**，或在崩溃时把字段路径打出来（现在是裸 `AttributeError`）。
2. **让 round-trip 支持"只校验我这一版词表"**（哪怕只是 `structure` + 一个 `unknown-host` 的明确 `skip`），别让新宿主恒 FAIL 且零诊断。
3. **给 `pt_scaffold` 加 `schema_path` 参数**，并让生成的 `run_demo.py`/`fake_host.py` 的 host 从 schema 取，而不是硬编码 `SKY`；否则缺口 C 的闭环永远断裂。
